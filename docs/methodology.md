# Методика расчёта

Документ описывает формулы, допущения и границы модели так, чтобы расчёт можно было
**независимо повторить вручную или в Excel**, не читая исходный код.

Все ставки и условия берутся только из `data/tariffs.json`. В коде нет ни одной
зашитой ставки: расчётное ядро (`src/core/calc.js`) умеет применять тарифные модели,
но не знает значений.

---

## 1. Обозначения

| Символ | Смысл | Откуда |
| --- | --- | --- |
| `A` | сумма одного платежа, ₽ | ввод пользователя |
| `T` | оборот за месяц, ₽ | ввод пользователя |
| `N` | число терминалов (только ПОС) | ввод пользователя |
| `r` | ставка из тарифного документа, % | реестр |
| `F` | абонентская (фиксированная) плата за месяц, ₽ | реестр |
| `cap` | ограничение платы за одну операцию, ₽ | реестр |
| `M` | минимальный месячный платёж, ₽ | реестр |
| `S` | размер пакета, ₽ | реестр |
| `P` | цена пакета, ₽ | реестр |
| `v` | ставка НДС, % | реестр |

Промежуточные величины не округляются. Округление до копеек применяется **только к
итоговым суммам**: `round(x × 100) / 100`, половина — вверх. Это совпадает с
правилом Альфа-Банка (п. 4 общих условий: доли копеек от 0,5 — вверх, меньше —
вниз).

Порядок применения: сначала ставка и ограничение за операцию, затем минимальный
месячный платёж и фиксированная плата, и только потом НДС.

---

## 2. Плата без НДС по моделям тарифа

### 2.1. Чистый процент — `percent`

Используется для карточных тарифов Уралсиба и ЮKassa.

```
плата с платежа      = A × r / 100
плата за месяц       = T × r / 100 + F
```

Компоненты платы складываются со ставкой до умножения: `r_итог = r + Σ r_комп`.
Компонент может быть **обязательным**: ставка ЮKassa 2,8 % опубликована только
в связке «2,8 % + 1 % за чек», то есть вместе с услугой «Чеки от ЮKassa».
При её отключении тариф по картам публично не опубликован, поэтому расчёт не
выполняется, а не подставляется «голая» ставка 2,8 %.

### 2.1а. Ступенчатая месячная плата с доплатой сверх порога — `tiered_fixed_plus_overage`

Модель тарифа «Фиксированный» Альфа-Банка (пп. 2.4.1–2.4.2).

```
ступень               = первая, у которой T ≤ верхняя_граница   (границы включающие)
плата за месяц        = плата_ступени
если T > 2 000 000:     расчёт не выполняется
```

Ступени (без НДС): до 100 000 ₽ — 1 690; до 300 000 — 4 980; до 500 000 — 8 270;
до 1 000 000 — 15 260; свыше 1 000 000 — 30 250 ₽. Порог ступени считается по
**общей сумме операций по картам и через СБП** за отчётный месяц.

Сверх 2 000 000 ₽ тариф добавляет 2,6 % (минимум 5 ₽) с каждой операции —
в дополнение к фиксированной плате, а не вместо неё. Из тарифа не следует,
какие именно операции попадают под доплату и в какой последовательности, поэтому
выше порога сервис отказывает в расчёте, а не назначает сумму.

### 2.2. Процент с минимальным платежом — `percent_with_min`

```
по ставке            = T × r / 100
минимум              = M × N            (если минимум установлен за терминал)
плата за месяц       = max(по ставке, минимум) + F
```

Минимум — это **нижняя граница месячной платы**, а не доплата сверху. Пока
`T × r / 100 < M × N`, продавец платит минимум, и эффективная ставка растёт обратно
пропорционально обороту. Минимум перестаёт действовать при обороте
`T* = M × N / (r / 100)`.

### 2.3. Пакетная плата — `package`

Семантика взята из опубликованного примера банка: пакет покупается **на каждый
терминал**, лимиты терминалов **суммируются**, при превышении суммарного лимита
докупается ещё один пакет и лимит растёт на его размер.

```
включённый лимит     = S × N
если T ≤ включённый лимит:   пакетов = N
иначе:                       пакетов = N + ⌈(T − S × N) / S⌉
плата за месяц       = пакетов × P + F
```

Плата **не привязана к отдельному платежу**, поэтому комиссия с одного платежа в этой
модели не определяется — сервис так и пишет, а не делит плату на число платежей.

### 2.4. Ступенчатый процент — `percent_tiered`

Ступень выбирается по месячному обороту: подходит та, для которой
`порог_входа ≤ T < порог_выхода`. При пересечении диапазонов берётся ступень с
наибольшим порогом входа. Далее — как в 2.1.

### 2.4а. Ограничение платы за одну операцию — `cap_rub`

```
плата с операции      = min(A × r / 100, cap)
операций за месяц     = округлённое до целого T / A
плата за месяц        = операций × плата_с_операции
```

Ограничение задано на одну операцию, поэтому месячная плата из оборота напрямую
не выводится. Число операций — целое: операция неделима. Если `T / A` не целое,
результат помечается как **оценка**, а дробное число операций не используется.

### 2.5. Ставка по категориям — `percent_by_category`

Расчёт **не выполняется**: опубликованы ставки для отдельных категорий продавцов, в
которые выбранный профиль не попадает. Подставить ставку чужой категории нельзя.

## 3. НДС

С 01.01.2026 комиссия за эквайринг облагается НДС по ставке 22 %. НДС начисляется
**на комиссию банка**, а не на сумму платежа, и является надбавкой — тарифная ставка
по договору от него не меняется.

```
НДС                  = плата_без_НДС × v / 100
итого                = плата_без_НДС + НДС
```

Эквивалентная запись через множитель: `итого = плата_без_НДС × (1 + v / 100)`.
Для `v = 22 %` ставка 2,69 % превращается в `2,69 × 1,22 = 3,2818 %`, что совпадает с
опубликованным банком значением «с НДС комиссия 3,28 %».

**НДС не начисляется на платежи через СБП** — это заявляют и Альфа-Банк, и Т-Банк.
В реестре это зафиксировано полем `vat.applies = false` у всех записей со способом
оплаты «СБП», и соответствие проверяется тестом.

## 4. Эффективная ставка

```
эффективная ставка, % = итого_за_месяц / T × 100
```

Это **вся плата за месяц, поделённая на оборот** — величина, сопоставимая между
тарифами с разной структурой платы (процент, минимум, пакет). Именно она отложена на
первом графике сервиса. Для чистого процента она равна `r × (1 + v/100)` и не зависит
ни от `T`, ни от `A`; для минимумов и пакетов — зависит.

## 5. Предельное значение Банка России

Считается **отдельно от предложений** и никогда не смешивается с ними.

```
предел с платежа     = min(A × r_пред / 100,  ограничение_за_перевод)
```

Для нашего профиля `r_пред = 0,40 %`, ограничение `1 500 ₽ за перевод`:
MCC 5399 относится ко **2-й группе** операций («потребительские товары и товары
повседневного спроса»), что подтверждается перечнем MCC в разделе 15 тарифов
Уралсиба. Ограничение включается с суммы платежа
`1 500 / 0,004 = 375 000,00 ₽`.

> Это верхняя граница, установленная регулятором. Она **не является тарифом какого-либо
> банка** и не может использоваться вместо него.

## 6. Когда расчёт не выполняется

Сервис различает три исхода и никогда не выдаёт число вместо отказа. Отказ не содержит
сумм — это проверяется тестом.

| Исход | Когда | Что показывает сервис |
| --- | --- | --- |
| `ok` | ставка однозначна и условия выполнены | суммы, ставку, разбор расчёта, источник |
| `not_applicable` | ставка однозначна, но параметры вне условий её применения | какой порог не выполнен и почему ставка не применяется |
| `not_determinable` | публичных данных не хватает, чтобы определить ставку | причину: «от …», индивидуальные условия, иная категория, нет действующих данных |

Коды причин отказа: `open_ended_rate` («от …»), `individual_terms`
(«рассчитывается индивидуально»), `indeterminate_rate` (ставка не раскрыта числом),
`rate_not_on_verified_page`, `no_verifiable_current_data`, `category_mismatch`,
`below_min_turnover`, `above_max_turnover`.

**Ни одна отсутствующая величина не достраивается предположением.**

## 7. Что в модель не входит

Сознательные границы модели — их нужно учитывать при чтении результатов:

- **Плата за расчётный счёт.** Тарифы ПОС-эквайринга Т-Банка привязаны к тарифам счёта
  (490 / 1 990 / 4 990 ₽ в месяц). Это плата за другую услугу, и в расчёт эквайринга
  она не включена.
- **Аренда и стоимость оборудования**, подключение, онлайн-кассы.
- **Возвраты и chargeback** — условия не опубликованы ни одним провайдером.
- **Срок зачисления** — упоминается в реестре как условие, но в деньги не переводится:
  для этого потребовалась бы стоимость денег для продавца, которой у нас нет.
- **Межбанковское вознаграждение (МБВ) и interchange** — это расчёты между участниками,
  а не плата продавца.
- **Структура продаж продавца** — доля карт и СБП, средний чек, число платежей.
  Это данные конкретного бизнеса; подставлять их означало бы выдумывать статистику.
  Поэтому сервис считает по **введённым** сумме платежа и обороту.

## 8. Как повторить расчёты независимо

```bash
npm test     # 47 проверок: реестр, формулы, 16 случаев ручной сверки
npm run checks   # docs/manual-check.csv и docs/tariff-data.csv
npm run docs     # пересобрать docs/registry.md из реестра
npm run build    # статическая сборка в dist/
```

- `docs/manual-check.csv` — по каждому случаю: параметры, **ручная арифметика строкой**,
  ожидаемое значение, фактическое значение ядра, отметка о совпадении и, где есть,
  цитата источника с тем же числом. Файл открывается в Excel (разделитель `;`, BOM).
- `docs/tariff-data.csv` — плоская выгрузка всех исходных данных со ссылками,
  датами действия и обращения.

Одиннадцать проверочных случаев сверены не с нашим кодом, а с числовыми примерами и формулировками, опубликованными самими банками.

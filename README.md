# Сервис сравнения открытых условий приёма платежей

Курсовая работа. Прототип рассчитывает стоимость приёма платежей **по картам** и
**через СБП** по актуальным общедоступным тарифам и для каждого результата показывает,
**из какого документа** он получен и **при каких условиях** применим. Если публичных
данных не хватает, сервис объясняет, **почему расчёт невозможен**, вместо того чтобы
подставить предположение.

**Контекст сопоставления:** приём платежей на сайте (интернет-эквайринг).
**Профиль продавца:** розничная интернет-торговля непродовольственными товарами, MCC 5399.

## Быстрый старт

Зависимостей нет — нужен только Node.js 20+.

```bash
npm test          # 47 проверок, включая 23 случая ручной сверки расчётов
npm run build     # статическая сборка в dist/
npm run serve     # http://localhost:5173
```

Остальные команды:

```bash
npm run checks    # docs/manual-check.csv + docs/tariff-data.csv
npm run docs      # пересобрать docs/registry.md из data/tariffs.json
```

## Ключевые результаты

- **По картам** условия определимы у трёх провайдеров из четырёх, но устроены
  по-разному: у Альфа-Банка это **ступенчатая месячная плата** (1 690–30 250 ₽),
  у Уралсиба — 2,45 % от платежа, у ЮKassa — 2,8 % + 1 % за чек. Прямое
  сравнение «кто дешевле» некорректно: структура платы разная.
- **Сверх 2 млн ₽/мес у Альфа-Банка расчёт не выполняется**: тариф добавляет
  2,6 % с операции, но какие операции попадают под доплату, из документа
  не следует.
- **По СБП сравнение по публичным данным невозможно**: ни один провайдер не публикует
  однозначную ставку («от 0 %», «рассчитаем индивидуально», либо ставки нет).
  Единственное твёрдое публичное число — предел Банка России, который **не является
  тарифом банка**.
- **НДС 22 % с 01.01.2026** начисляется на карточную комиссию и **не начисляется на СБП**.
  Он превращает ставку 2,45 % в 2,99 %, а плату 30 250 ₽ — в 36 905 ₽.

Подробно — в `docs/analytical-note.md`.

## Проверяемость

Каждая запись реестра содержит ссылку на документ, дату действия, **дату обращения**,
способ проверки, дословные цитаты и перечень параметров, которых не хватает для расчёта.
Отдельная страница «Источники» показывает всё это в интерфейсе.

Проверочные случаи сверены не с нашим кодом, а с **формулировками и числами из
официальных тарифных документов** (например, Альфа-Банк, п. 2.4.1: «по 100 000
рублей (включительно) — 1690 руб.»).

## Ограничение доступа к данным

Сайты `tbank.ru`, `alfabank.ru` и `uralsib.ru` обслуживаются по сертификатам
**Russian Trusted Root CA** (Минцифры РФ); без установленного корневого сертификата
загрузка страниц прерывается ошибкой проверки TLS.

Условия Альфа-Банка взяты из официального тарифного документа, действующего
с 21.10.2026 (пп. 2.4.1–2.4.2, стр. 82–83). Условия Уралсиба — из официальных
тарифных XLSX. Данные Т-Банка подтверждены на живых страницах.

Остаётся подтвердить у ЮKassa состав вознаграждения за сервис чеков и режим НДС
по нему: публичные тарифы раздельный режим НДС не определяют.

## Граница выводов

Работа сравнивает **стоимость публично описанных условий**. Она не утверждает, какой
способ оплаты выгоднее конкретному магазину: для этого потребовались бы его договоры,
структура продаж и данные о поведении покупателей. Суммы, введённые пользователем или
использованные в проверках, — **аргументы расчёта**, а не статистика бизнеса.

## Публикация

GitHub Actions (`.github/workflows/pages.yml`) на каждый push в `main`/`master`:
запускает тесты, проверяет, что `docs/registry.md` не разошёлся с реестром, собирает
`dist/` и публикует на GitHub Pages. Публикация **заблокирована**, если расчёт
расходится с ручной проверкой.

Чтобы включить: в настройках репозитория **Settings → Pages → Source → GitHub Actions**.
